# LUMI REELS — 光を、つかまえよう。

v1.1（2026-10-09）：中段を狙った図柄が上下段・斜めラインに分かれる停止制御を修正しました。中段を最優先し、横ライン、斜めラインの順に引き込みます。ランプ点灯後は、狙う図柄が7かBARかも表示します。保存データは引き続き使えます。

告知ランプと全3リールの目押しを楽しむ、仮想メダル専用のオリジナルブラウザスロットです。通常遊技からBIG／REGの終了までプレイできます。名称、ロゴ、図柄、効果音、BGMは本プロジェクト用に制作しました。

## すぐに公開する

**公開用のindex.htmlには、CSS・JavaScript・SVG図柄・音声合成の実装がすべて入っています。index.html単体をGitHub Pagesの公開ルートに置いて動作します。** 外部CDN、音声ファイルのダウンロード、ビルド作業、npm installはプレイ時に必要ありません。

1. このindex.htmlをダウンロードします。ZIPを使う場合はlumi-reelsフォルダ内のindex.htmlを使います。
2. GitHubでPagesを利用できるリポジトリを開き、Add file → Upload filesでindex.htmlを公開ルートにアップロードしてコミットします。既存のindex.htmlを置き換える場合は、置き換えるゲームが正しいか確認してください。
3. Settings → PagesでSourceをDeploy from a branchにし、Branchをmain、フォルダを/(root)にしてSaveします。ブランチ名が異なる場合はアップロードしたブランチを選びます。
4. 公開が完了したら、Pages画面に表示される公開URLをiPhone／iPadのSafariで開きます。
5. 3枚BETをタップし、レバー、3つの停止ボタンで遊びます。

公式の公開手順：https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site

iOSのファイルプレビューではJavaScriptが実行されない場合があります。iPhone／iPadでは公開URLをSafariで開いてください。公開版：https://hiroshi6844.github.io/test/lumi-reels/

## 操作

| 操作 | 画面 | PCキーボード |
| --- | --- | --- |
| メダルを入れる | 3枚BET | B |
| 回転開始 | レバー | Space／Enter |
| 各リールを止める | 左・中・右の停止ボタン | 1・2・3 |
| 一時停止・復帰 | Ⅱ／タップして再開 | P |
| 消音・解除 | ♪ | M |
| 音量・滑り・速度・設定 | 歯車 | — |
| 遊び方 | ? | — |

初期メダルは1,000枚。BETできる枚数を下回ると補充ボタンで1,000枚加算できます。メダル、設定、遊技データ、ボーナス持ち越し、ボーナス消化状況を端末内に保存します。保存できない環境でも遊技は続けられます。回転中・払い出し中に再読み込みした場合は、再開ボタンで続きから復帰します。

総ゲーム数は通常・ボーナス両方のレバー操作を数えます。「ボーナス後」は通常ゲームのみを数え、ボーナス終了時に0に戻ります。初回ボーナス前は開始からの通常ゲーム数です。

## リール・目押し・滑り

- 固定24コマの3リールが上から下に回転し、上下3段の合計9マスを表示します。
- 横3本、斜め2本が有効ライン。成立ラインは実際の図柄の中心を通る線で表示します。
- レバーで役を決め、停止操作では抽選し直しません。停止ボタンを押した時点の実際の位置を使います。
- ランプの下に狙う図柄（7／BAR）を表示します。中段を目安に狙ってください。
- 7とBARは、左・中・右すべてで目押しが必要です。どの停止順でも狙えます。1リールだけ合わせて残りが自動的に揃う制御にはしていません。
- 通常の最大滑りは4コマ。3〜6コマで調整できます。進む距離には端数を含み、後ろの停止位置へは戻りません。
- 到達できる範囲の当選図柄だけを引き込みます。届かなければ取りこぼし、ボーナス当選とランプ点灯を次のゲームに持ち越します。
- 滑りは等速区間から最後の最大0.12秒だけ減速。停止時に逆回転・急加速・図柄の飛びを発生させません。
- 小役・リプレイの抽選がボーナス持ち越しと重なるゲームでは、小役・リプレイを優先します。ボーナスは持ち越します。
- 内部当選していない役が有効ライン上に揃う停止位置を排除します。
- 目押しガイドをONにすると、ランプ点灯中にボーナス図柄を引き込める停止ボタンが緑になります。ガイドを使っても各リールの停止操作は必要です。

## 告知とボーナス

通常時のボーナス当選は、先告知50%／後告知50%です。先告知はレバー時、後告知は第3停止後にランプが光ります。後告知とボーナス図柄成立が同じゲームでも、点灯を0.25秒表示します。

| 図柄・役 | 成立・内容 | 払い出し |
| --- | --- | --- |
| 7・7・7 | BIG開始、50G継続 | 開始時の一括加算なし |
| BAR・BAR・BAR | REG開始、20G継続 | 開始時の一括加算なし |
| ぶどう3つ | 有効ライン上で成立 | 8枚 |
| チェリー3つ | 有効ライン上で成立 | 2枚 |
| ベル3つ | 有効ライン上で成立 | 10枚 |
| リプレイ3つ | 次のゲームがBET済みになる | メダルの追加消費なし |
| スター | 演出用図柄 | 0枚 |

ボーナス中もBET・レバー・3リール停止を操作します。どのタイミングで止めても中段にぶどうが揃います。ボーナス専用の自動制御は最大6コマの前進だけで成立させます。通常時の目押し制御とは区別し、目押し不要を保証します。

毎ゲーム3枚BET、ぶどう8枚払い出し。残りGは8枚をすべて払い出した後に減ります。50G完走のBIGは純増250枚、20G完走のREGは純増100枚です。ボーナス成立までの通常ゲームのBETは、この純増表示に含めません。最終ゲームの払い出しが完了してから通常状態へ戻ります。

## 設定1〜6の確率

**すべてゲーム独自の値です。実在する機種の確率ではありません。** ボーナス未当選の通常ゲームで、各レバー操作について排他的に抽選します。合成はBIG・REGの確率を足した値です。

| 設定 | BIG | REG | ボーナス合成 | ぶどう | チェリー | ベル | リプレイ |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 1/240 | 1/360 | 1/144.0 | 1/6.5 | 1/32 | 1/96 | 1/7.3 |
| 2 | 1/225 | 1/315 | 1/131.2 | 1/6.4 | 1/32 | 1/96 | 1/7.3 |
| 3 | 1/210 | 1/280 | 1/120.0 | 1/6.3 | 1/32 | 1/96 | 1/7.3 |
| 4 | 1/195 | 1/245 | 1/108.6 | 1/6.2 | 1/32 | 1/96 | 1/7.3 |
| 5 | 1/180 | 1/215 | 1/98.0 | 1/6.1 | 1/32 | 1/96 | 1/7.3 |
| 6 | 1/165 | 1/185 | 1/87.2 | 1/6 | 1/32 | 1/96 | 1/7.3 |

残りの確率はハズレです。小役の表示・払い出しは停止結果で決まります。ボーナス持ち越し中は新しいBIG・REGを抽選せず、小役の確率は維持します。ボーナス中はぶどう確定です。

設定変更は「通常時・BET前・ボーナス非当選」に限ります。変更するとメダルは1,000枚、遊技データは0に戻るため設定別の結果が混ざりません。

## 調整とソース

ゲームの確率・払い出し・BET・ボーナスG数・回転速度・最大滑り・告知割合は **src/config.jsの一か所** で調整します。BET、ボーナス条件、払い出し一覧、確率表は設定値から画面にも反映します。

編集後はPython 3で次を実行してindex.htmlを再生成します。

```bash
python3 build.py
```

ZIPにはsrc/config.js、src/engine.js、src/app.js、src/audio.js、src/style.css、src/page.html、src/qa.jsと元のSVG素材を含めています。engine.jsはDOMから独立した状態機械、app.jsは描画・操作・保存、audio.jsは効果音とオリジナルBGMです。

開発時のプレビューはNode.jsで次を実行できます。追加のパッケージは不要です。

```bash
npm run dev
```

その後、ローカルの http://localhost:4173/ をブラウザで開きます。完成したindex.htmlを公開する際にこのサーバーは必要ありません。

## 開発モード・検証

公開URLの末尾に **?dev=1** を付けると開発モードが表示されます。

- 次のレバーの役、先告知／後告知を強制指定できます。
- リール位置、内部当選、状態、払い出し途中の情報、音声の状態を確認できます。
- 各リールの「内部役を狙って停止」「取りこぼして停止」で成功と失敗を再現できます。位置を変更する操作は検証用です。
- 「エンジン検証を実行」でブラウザ内に検証結果を表示します。検証中は数秒〜十数秒処理が集中します。
- 通常プレイと開発モードの保存領域は別です。開発モードの初期化は通常プレイのデータを変更しません。

Node.jsでエンジン検証を実行する場合：

```bash
npm test
```

設定・払い出しなどの初期仕様を変更した場合は、変更に対応するテスト期待値と説明も更新してください。リール配列を変更する場合は、非当選役の排除とボーナス自動停止を含む検証を必ず再実行してください。

tests/viewport.htmlは縦横7サイズでの表示と画面回転を、tests/storage-disabled.htmlは保存不可の環境を確認するページです。いずれも開発時に使う検証用ファイルです。

**実際の確認環境と未確認範囲はTEST_RESULTS.mdに記載しています。iPhone／iPadのSafari実機確認は行っていません。**
